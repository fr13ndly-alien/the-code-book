# React Router edges Astro for ciphers

Build the site as a **Vite 8 + React 19 single-page app on React Router 8.5 in framework mode (`ssr: false` plus a `prerender` list)**, render 3D with **React Three Fiber 9.8 + drei 10.7 on a pinned three r187 `WebGLRenderer`**, author chapters in **MDX**, keep state in **Zustand 5 persisted behind a small storage interface**, add offline with **vite-plugin-pwa 2.0**, and host on **Cloudflare's free static tier**. The deciding fact is not web performance but the phone path: Capacitor's iOS router serves the root `index.html` for every URL without a file extension, which suits a client-routed SPA and breaks a multi-page Astro site unless you patch links or native code. Astro 7 is the runner-up and the better pure reading site (0 KiB of JavaScript against 115 KiB in the one current benchmark), but that gap disappears next to three.js on the 3D pages and inside a locally bundled app. The largest risks are iOS killing the WebGL process without firing an event, Safari deleting a tab user's progress after seven days, App Store guideline 4.2, and Creative Commons models inside an App Store binary. Three caveats on the evidence: no source tested this exact combination (prerendered site + PWA + Capacitor), so the framework verdict is a reasoned inference; several mobile limits are practitioner reports rather than published numbers; and the monorepo tooling itself was not researched. A one-week prototype of a single Enigma page, wrapped in Capacitor and tested on a real iPhone, settles most of what is still open.

## Capacitor's root-index fallback makes the SPA shape the safer bet

### The recommended stack at a glance

Tutorials dated 2025 describe Astro 5, React Router 7 and pre-1.0 TanStack Start and are stale on API details: React Router 8 shipped on 17 June 2026, is ESM-only, and removed the `react-router-dom` package ([React Router v8 blog](https://remix.run/blog/react-router-v8)).

### Why the wrapper, not the web, decides

Capacitor's iOS router returns `index.html` from the bundle root **whenever the requested path has no file extension**; the source comment calls such a path "a SPA route" ([Router.swift](https://github.com/ionic-team/capacitor/blob/main/ios/Capacitor/Capacitor/Router.swift)). An Astro build emits `/vigenere/index.html` by default ([Astro config reference](https://docs.astro.build/en/reference/configuration-reference/)), so a tap on `/vigenere/` inside the app would return the home page. The escape routes exist (emit `.html` files and link to them explicitly, or override the replaceable `router()` method on `CAPBridgeViewController` in Swift ([CAPBridgeViewController.swift](https://github.com/ionic-team/capacitor/blob/main/ios/Capacitor/Capacitor/CAPBridgeViewController.swift))), but neither Astro nor Capacitor documents them, and the research found no production Astro site shipped this way on iOS.

React Router supports the needed hybrid officially. With `ssr: false` and a `prerender` list, each cipher URL gets its own `index.html` for the web, and the build also writes an SPA fallback page that can boot at any path ([React Router pre-rendering docs](https://reactrouter.com/how-to/pre-rendering)). The sensible plan is **two build targets from one codebase**: a prerendered web build, and a pure SPA-mode build whose root `index.html` is the shell, pointed at by Capacitor's `webDir`. That second target has not been tested by anyone in the sources, and how `.data` files behave under the `capacitor://` scheme is unconfirmed, so it sits at the top of the prototype list.

The 3D layer pushes the same way. R3F's maintainer advises keeping one canvas alive and swapping its contents rather than mounting a canvas per route ([three.js forum](https://discourse.threejs.org/t/context-lost-when-i-route-to-another-page-in-react-three-fiber/61736), a 2024 thread). That is trivial in one React tree. In Astro each island is a separate React root that cannot share context ([Astro islands state recipe](https://docs.astro.build/en/recipes/sharing-state-islands/)), and nothing documents whether `transition:persist` keeps a WebGL context alive across pages.

### Runner-up: Astro 7.4 with React islands

Astro wins on the open web. In Nolan Lawson's October 2026 throttled-mobile benchmark of a content-style app, Astro 7.4 shipped **0 KiB of JavaScript with an 810 ms LCP**, against 115 KiB and 1,729 ms for React Router 8.5, 118 KiB for TanStack Start and 142 KiB for Next.js 16.4 ([Nolan Lawson](https://nolanlawson.com/2026/10/28/the-ai-cost-of-javascript-frameworks/)). The author notes the test disallowed prerendered HTML and that Lighthouse favours multi-page sites, so the gap narrows for a static React Router build; all four scored 99 to 100. Astro also has the only first-party typed content layer, though Astro 7's new Rust Markdown pipeline requires opting back into the legacy pipeline to use remark or rehype plugins such as maths rendering ([Astro 7 blog](https://astro.build/blog/astro-7/)).

Choose Astro instead if the phone app becomes a native rewrite rather than a Capacitor wrap, because then the router conflict never arises. To keep that door open, write every simulation as a plain React component with no framework imports and keep Astro-specific or router-specific syntax out of MDX bodies; a later switch is then a routing and layout rewrite, not a content rewrite.

TanStack Start offers the same two modes as React Router but declared 1.0 only on 13 October 2026 ([TanStack Start 1.0 blog](https://tanstack.com/blog/tanstack-start-1-0)), which is too young for a multi-year solo project. Next.js static export works but disables rewrites, redirects, headers, image optimisation and server actions ([Next.js static exports guide](https://nextjs.org/docs/app/guides/static-exports)), leaving most of the framework unused.

### Monorepo layout with a DOM-free engine

The research did not compare workspace tools, so treat the tooling as a default rather than a finding: plain package-manager workspaces are enough for three packages, and versions should be checked at setup. The structure matters more than the tool.

```
the-code-book/
  packages/
    cipher-engine/     pure TypeScript; tsconfig "lib": ["ES2022"] with no "DOM";
                       no React, three or browser imports; all cipher logic and tests
    sims/              React components (2D widgets, R3F scenes); imports engine only
  apps/
    web/               React Router 8 app, MDX chapters, PWA config, storage adapter
    ios/               added later: Capacitor project, webDir -> SPA build of apps/web
  assets/
    source/            lossless GLBs exported from Blender (.blend kept out of git or in LFS)
    scripts/           glTF-Transform recipe; writes hashed GLBs into apps/web/public
  CREDITS.md           one line per third-party asset
```

Omitting `DOM` from the engine's compiler libraries makes the type checker enforce the boundary. The engine holds state and transitions (rotor positions, plugboard, message) so that the 3D scene, the accessible DOM controls and any future native UI are all renderers over the same state. For Enigma, the rotor and reflector wirings published by Crypto Museum and Wikipedia agree letter for letter ([Crypto Museum](https://www.cryptomuseum.com/crypto/enigma/wiring.htm), [Wikipedia](https://en.wikipedia.org/wiki/Enigma_rotor_details)), and the MIT-licensed enigma-python carries unit tests against a 1930 Army message and a 1945 U-534 M4 message that can be ported as oracles ([enigma-python](https://github.com/denismaggior8/enigma-python)). How a fully native Swift app would consume the TypeScript engine was not researched.

## One WebGL context and a pinned renderer keep iPhones alive

**Stay on `WebGLRenderer`.** WebGPU ships in iOS Safari 26 and Android Chrome 121+, but R3F 10, which makes WebGPU the default, is still at alpha.6 with no beta date ([R3F releases](https://github.com/pmndrs/react-three-fiber/releases)), and a May 2026 forum benchmark measured WebGPURenderer at roughly twice the CPU time and five times the first-frame time of WebGLRenderer on a many-mesh scene ([three.js forum](https://discourse.threejs.org/t/webgpurenderer-2x-slower-cpu-and-5-10x-slower-first-frame-than-webglrenderer-on-many-mesh-scenes-r183-same-on-both-backends/91904)). That was a single desktop machine, but for a few dozen meshes there is nothing to gain. Pin `three` exactly: releases land every 7 to 11 weeks and carry breaking changes, such as the removal of `PCFSoftShadowMap` in r186 ([Utsubo](https://www.utsubo.com/blog/threejs-2026-what-changed)). Use R3F 9.8.2 or later, which fixed disposal on unmount and a demand-mode rendering bug. Expect one migration to R3F 10 and drei 11 during the project's life.

R3F beats Svelte with Threlte on ecosystem rather than speed. No credible head-to-head benchmark exists, and with on-demand rendering the wrapper is not the bottleneck. R3F has about **9.2 million weekly downloads against Threlte's 116 thousand** ([npm downloads API](https://api.npmjs.org/downloads/point/last-week/@react-three/fiber), [Threlte](https://api.npmjs.org/downloads/point/last-week/@threlte/core)). Both have maintenance concentration: drei saw only 11 commits between May and November 2026, and one person wrote 81 of Threlte's latest 100 ([drei commits](https://api.github.com/repos/pmndrs/drei/commits?per_page=100&since=2026-05-01T00:00:00Z), [Threlte commits](https://api.github.com/repos/threlte/threlte/commits?per_page=100&since=2026-05-01T00:00:00Z)). Avoid depending on `@use-gesture/react` (last release March 2024) or `@react-three/a11y` (last release May 2022); R3F's native pointer events with pointer capture cover rotor and disc dragging ([R3F events docs](https://r3f.docs.pmnd.rs/api/events)).

The mobile design rules follow from how iOS fails. Apple publishes no memory ceiling ([Apple Developer Forums](https://developer.apple.com/forums/thread/771787)); practitioner guidance is to stay under roughly 256 MB of GPU memory on older iPhones ([abratabia](https://abratabia.com/mobile-web-games/ios-safari-gotchas.php)). An open WebKit bug records pages being terminated with **no `webglcontextlost` event and no error reaching JavaScript** ([WebKit bug 300782](https://bugs.webkit.org/show_bug.cgi?id=300782)), and a developer who shipped a three.js game through Capacitor in September 2026 found the same in WKWebView and resorted to polling `isContextLost()` every two seconds ([raxxo](https://raxxo.shop/blogs/lab/shipping-a-three-js-game-to-the-ios-app-store)). So: keep exactly one canvas mounted for the session, use `frameloop="demand"` so an idle device costs nothing ([R3F performance docs](https://r3f.docs.pmnd.rs/advanced/scaling-performance)), cap device pixel ratio at 2, skip post-processing and real-time shadows, and recover from context loss by remounting the canvas from cached models. Because the engine holds all simulator state outside the scene graph, a remount or a forced page reload loses nothing.

Published performance budgets are rules of thumb that disagree widely; R3F's own docs suggest a few hundred draw calls at most, not specific to mobile ([R3F performance docs](https://r3f.docs.pmnd.rs/advanced/scaling-performance)). A reasonable working target, to be validated on devices, is 50 or fewer draw calls and under 200 thousand triangles per scene. The Enigma is the stress case: 26 keys, 26 lamps and 26 sockets should each be one instanced mesh.

Touch needs a deliberate design. `OrbitControls` sets `touch-action: none` on its element, which blocks page scrolling over the canvas ([OrbitControls source](https://raw.githubusercontent.com/mrdoob/three.js/dev/examples/jsm/controls/OrbitControls.js)). For a model embedded in scrolling prose, let horizontal drags rotate and vertical drags scroll (`touch-action: pan-y`), and reserve free orbit for a full-screen mode. Mirror every 3D control with real DOM controls and a text readout; this is the accessibility path and also the fallback when WebGL fails.

## Build most devices in code; only three have usable free models

A search of Sketchfab's downloadable catalogue found credible free models for only three object groups: the Enigma, the Rosetta Stone, and generic props such as barrels, padlocks and chests. **No downloadable, openly licensed mesh turned up for the scytale, cipher disc, Linear B tablet, Polish bomba, Turing bombe, Lorenz machine or Colossus** ([Sketchfab search API](https://api.sketchfab.com/v3/search?type=models&q=turing%20bombe&downloadable=true)). Other repositories (Smithsonian, Wikimedia Commons, museum sites) were not checked individually.

| Object | Route | Source if not self-made |
|---|---|---|
| Enigma | Model in Blender from primitives, one named node per moving part | Fallback: [CC BY prop, 148k faces](https://sketchfab.com/3d-models/enigma-machine-30b85c037a164174a109ad6f002b9c47), hierarchy unknown |
| Scytale, cipher disc, wax tablet, optics bench, strongbox, Linear B slab | three.js primitives with generated lettering | none needed |
| Barrel | Poly Haven Wine Barrel 01 | [CC0, 10.8k polys](https://polyhaven.com/a/wine_barrel_01) |
| Rosetta Stone | Low-poly CC BY model, or decimated museum scan on the web only | [CC BY, 1.5k faces](https://sketchfab.com/3d-models/rosetta-stone-ultra-low-poly-a9efe7bf59c14f39807115fa2379c363); [British Museum scan, CC BY-NC-SA, 480k faces](https://sketchfab.com/3d-models/the-rosetta-stone-1e03509704a3490e99a173e53b93e282) |
| Bomba, bombe, Lorenz, Colossus | Stylised low-poly own build, or 2D illustration | none found |

The museum Enigma scan (330 thousand triangles, CC BY-NC-SA) is a fused mesh and cannot provide separable rotors or keys ([Science Museum Group on Sketchfab](https://sketchfab.com/3d-models/enigma-machine-1934-c8ee76c383654e3095ea4cc9e7990274)). AI generators are no shortcut for the hero model: the one AI-made cipher object found was a single 1,037,498-face mesh ([Sketchfab](https://sketchfab.com/3d-models/emerald-cipher-disk-dcf53e436aed418aad92437e6ba4756c)). The Enigma is mostly boxes, cylinders and discs, so primitive modelling with linked duplicates is within reach of a non-artist. For lettering, use canvas texture atlases on rotor rings, discs and keys, and SDF text (troika-three-text 0.53.1, via drei's `<Text>`) for labels ([troika on npm](https://www.npmjs.com/package/troika-three-text)).

**Pipeline.** Blender 5.2 LTS exports glTF with Principled BSDF materials, WebP textures and both Draco and Meshopt compression ([Blender 5.2 manual](https://docs.blender.org/manual/en/5.2/addons/scene_gltf2.html)). Export uncompressed GLB with applied scale and rotation, each moving part's origin on its rotation axis, and ASCII node names; then compress in a script with glTF-Transform 4.5.1 ([npm](https://www.npmjs.com/package/@gltf-transform/cli)). Choose Meshopt project-wide and WebP textures; community guidance, not benchmarks, says Meshopt decodes several times faster than Draco with a far smaller decoder ([Cinevva guide](https://app.cinevva.com/guides/optimize-glb-for-web)). KTX2 is worth testing only for a texture-heavy scan. Self-host decoders so the app works offline. Treat gltfjsx as a one-off scaffold at most: it has had no release since November 2024 ([npm](https://www.npmjs.com/package/gltfjsx)).

**Licensing.** A free, ad-free educational site falls within Creative Commons "NonCommercial", and ShareAlike attaches to a modified model file, not to the surrounding code ([CC FAQ](https://creativecommons.org/faq/)). The unresolved point is the App Store. CC licences forbid applying technological measures that restrict recipients' rights, and the FAQ's example of a violation is uploading to a platform that applies DRM ([CC FAQ](https://creativecommons.org/faq/)). Whether Apple's packaging counts was not verified, and this is not legal advice. The conservative rule: **the iOS build ships only CC0 and self-made assets**, which the build-in-code strategy above nearly achieves anyway.

## Eviction, not quota, shapes persistence, offline and hosting

Progress and settings amount to a few kilobytes, so storage quota never binds. Eviction does. Safari deletes all script-writable storage (localStorage, IndexedDB and service-worker caches) **after seven days of Safari use without interaction with the site**; a Home Screen web app has its own counter, and WebKit does not expect its data to be deleted ([WebKit ITP post](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/)). That exemption rests on a 2020 post and was not re-confirmed for iOS 26. localStorage and IndexedDB are covered by the same rules, so neither is safer; localStorage through Zustand's persist middleware is the simpler choice. The durable answer without a backend is an **export/import of progress as a versioned JSON file**, plus an in-page hint to add the site to the Home Screen and a call to `navigator.storage.persist()`, which WebKit grants on heuristics such as Home Screen installation ([WebKit storage policy](https://webkit.org/blog/14403/updates-to-storage-policy/)).

Inside Capacitor, the vendor's own guide says localStorage "must be considered transient" and recommends the Preferences plugin ([Capacitor storage guide](https://capacitorjs.com/docs/guides/storage)). The storage interface absorbs that swap, and because the app runs on its own origin, the export file doubles as the web-to-app migration path.

For offline, vite-plugin-pwa 2.0.0 declares peer support through Vite 8 ([package.json](https://raw.githubusercontent.com/vite-pwa/vite-plugin-pwa/main/package.json)). Its precache excludes files over 2 MiB by default ([Vite PWA FAQ](https://vite-pwa-org.netlify.app/guide/faq)); keep that guard. Precache the shell, scripts, styles and fonts; cache GLBs at runtime under content-hashed names; and offer an explicit "download all for offline" button rather than pulling tens of megabytes silently. Make the service worker switchable off at build time, since the Capacitor build ships assets in the bundle.

Cloudflare is the host. On Workers static assets, "requests to static assets are free and unlimited", with 20,000 files and 25 MiB per file on the free plan ([Cloudflare billing docs](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)); Pages has the same file limits and lists no bandwidth cap ([Pages limits](https://developers.cloudflare.com/pages/platform/limits/)). GitHub Pages is the fallback with a 100 GB monthly soft limit ([GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)). Netlify's free plan is now 300 credits at 20 credits per GB, about 15 GB, which is thin for 3D assets ([Netlify pricing](https://www.netlify.com/pricing/)). Cloudflare does not compress GLB in transit, so the build-time compression above is the only compression ([Cloudflare compression docs](https://developers.cloudflare.com/speed/optimization/content/compression/)); add a `_headers` rule marking hashed assets immutable. Host at a domain root so web and app builds share root-absolute asset paths.

## Four risks need mitigations; five prototypes come first

| Risk | Evidence | Mitigation |
|---|---|---|
| iOS kills the WebGL or web-content process silently | Open WebKit bug; Capacitor practitioner report | One canvas, small textures, poll `isContextLost()`, remount from cache, persist state on every change, static-image fallback after repeated failure |
| Hard reload at a sub-route inside Capacitor loads the wrong HTML | Capacitor source; untested with React Router | Separate SPA-mode build for the app; test forced reload and deep links |
| Tab users lose progress and offline cache after seven days | WebKit ITP post | Export/import, install hint, `persist()` |
| App Store rejection under guideline 4.2 | Guideline text; one 2026 forum case where added plugins did not help ([Apple forum](https://developer.apple.com/forums/thread/812889)) | All content bundled and working in airplane mode, no browser chrome, phone-fit touch UI, native progress storage and haptics, plain review notes |
| CC-licensed models inside an App Store binary | CC FAQ on technological measures | CC0 and self-made assets only in the iOS build |
| Dependency churn (three every 7 to 11 weeks, R3F 10, yearly React Router majors) | Release notes | Pin versions, upgrade deliberately, keep `sims/` free of framework imports |

Guideline 4.2 says an app must "elevate it beyond a repackaged website" ([App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)). A self-contained offline simulator is a stronger candidate than the rejected example, whose core flow lived on a third-party website, but no approval data exists for this kind of app. The Apple Developer Program costs 99 USD a year, and fee waivers exclude individuals ([Apple fee waivers](https://developer.apple.com/help/account/membership/fee-waivers/)). An installed PWA is therefore a sound interim phone app.

Prototype in this order, before writing chapters. First, the **end-to-end spike**: one Enigma page and one 2D page in React Router 8, prerendered for the web and built in SPA mode for Capacitor, then on a real iPhone test cold start, in-app navigation, a forced reload on a sub-route, a deep link and airplane mode. Xcode's free Personal Team allows on-device installs that expire after seven days ([Apple membership comparison](https://developer.apple.com/support/compare-memberships/)), so this costs nothing. Second, the **Enigma scene on an iPhone 12 or 13 class device and a mid-range Android phone**, in Safari and in WKWebView: log `renderer.info`, navigate between two scenes repeatedly to check for leaks, background the app, and exercise the recovery path. Third, the **engine**: Enigma in `cipher-engine` with the ported historical-message tests, reciprocity checks and a compile that proves no DOM types are reachable. Fourth, the **toolchain joins nobody has confirmed**: MDX in React Router 8 on Vite 8's Rolldown bundler, and vite-plugin-pwa caching the prerendered pages and `.data` files. Fifth, **storage and touch on a real iPhone**: the seven-day behaviour in a tab against the Home Screen app, the export/import round trip, and orbit-versus-scroll on an embedded model.

## Conclusion

The choice turned on a detail few framework comparisons mention: a line in Capacitor's Swift router. Because the wrapper assumes a single-page app, the stack that reads slightly worse on a web benchmark is the one that reaches the phone with the least undocumented work. If the phone plan changes to a native rewrite, the verdict flips toward Astro, which is why the portable parts (a DOM-free engine, framework-free simulation components, plain MDX) matter more than the framework itself.

The research also changed the shape of the 3D work. With no free models for most devices and licence friction on the rest, this is less an asset-sourcing problem than a small modelling and procedural-geometry project, with the Enigma as the one substantial Blender job. That is good news for phones: code-built devices are the lightest, sharpest and most licence-clean option available.
